## 2. Logo (`public/ahorrito-logo.svg`)

**Causa del peso.** El SVG incrusta la misma textura PNG (un degradado de 1048 × 1001 px) siete
veces, una por cada letra recortada. Las siete copias tienen el mismo hash SHA-256
(`db34c2b3eeffdd4e…`).

**Corrección.** La textura se declara una sola vez en `<defs>` como `<image id="textura-logo">`,
y cada letra la reutiliza con `<use>`. No se tocaron los trazos, los recortes, las
transformaciones, la paleta ni el `viewBox`.

| | Bytes |
|---|---|
| Antes | 3,037,529 |
| Después | 446,960 (−85.3 %) |
| Transferido con compresión (`pnpm start`) | 165,303 |

**Comparación píxel a píxel.** Ambos archivos se rasterizaron con `sharp` (librsvg) a tres
anchos y se compararon byte a byte en RGBA:

| Ancho | Tamaño | Bytes comparados | Píxeles distintos | Diferencia máxima |
|---|---|---|---|---|
| 160 px | 160 × 47 | 30,080 | 0 | 0 |
| 320 px | 320 × 95 | 121,600 | 0 | 0 |
| 1251 px | 1251 × 370 | 1,851,480 | 0 | 0 |

**Advertencia de precarga.** La causa no era el peso. `src/app/page.tsx` usaba `priority`, que
Next.js 16 depreca a favor de `preload`, y la documentación del marco
(`node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md`) recomienda
`loading="eager"` en lugar de precargar. Se cambió a `loading="eager"`.

Verificación contra `pnpm build` + `pnpm start`, en una pestaña nueva del navegador integrado
(Chromium 152):

- `<link rel="preload">` en `/`: solo el fragmento de JavaScript y la fuente; el logo ya no se
  precarga.
- La imagen carga con `loading="eager"`, `complete: true` y ancho natural de 1251 px.
- Consola en `/`, `/iniciar-sesion`, `/registro` y `/demo`: **"No console logs."** Antes del
  cambio aparecía `The resource http://localhost:3000/ahorrito-logo.svg was preloaded using link
  preload but not used…`.
